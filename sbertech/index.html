Making broken records visible

JTBD 1: When attributes fail to sync and I only find out because someone reports lost access, I want to see empty attributes and stale sync times right in the user list, so I catch broken records before they turn into tickets

Features added: an admin can spot issues easily, because the stale sync time is shown as ‘72h ago’ rather than a plain timestamp, and missing attributes are flagged as well.

Spotting the attribute that broke

JTBD 3: When a user can’t reach a resource their colleague can, I want to compare both sets of attributes, so I can spot the difference myself instead of reading raw files

Building a playground with a sandbox

JTBD 4: When I write a policy that decides who gets access, I want to test it against different users and conditions before it goes live, so I catch mistakes early

“It worked yesterday” — an investigation

JTBD Story 5: When a user loses access they had yesterday, I want to compare their attributes before and after in the ABAC UI, so I can see which one dropped without asking a developer to pull the data

Option A — the user searches, filters, and pins two history snapshots using the bulk-operation table controls, then clicks the compare button. Option B — the user finds the snapshot with no issues and compares it with the current state in one click.

Option A was attractive because it seemed easy to enable every possible table component feature. Option B won the tradeoff, because it compares the current snapshot with a chosen one in a single click, without the cumbersome table UI and its four-plus user clicks.
