Outcomes

The business got an in-house platform to set work shifts for retail employees and attracted major enterprise clients like Tele2 (Sweden) and Japan Tobacco International.

Situation

MA.direct shipped a successful MVP and gained many retail chain clients who need work shifts and tasks set for their staff, but client success managers can’t handle that volume. The product team is working on scaling core product features: client onboarding, task management, payouts, and report moderation tools. The goal is to retain clients and keep revenue coming.

Actions

  • Ran a kick-off with the product team
  • Interviewed internal tool users I could reach
  • Negotiated the roadmap using the impact-effort matrix
  • Prototyped solutions, collected feedback, prepared hand-off
  • Ran A/B tests for repeatable tasks (report review, taking a task from the list)

Problem

  • Managers set additional rewards for tasks in difficult locations manually
  • Managers have no tool to set and manage shifts and tasks in bulk
  • Managers can’t see report collection progress by region
  • Moderators lose time on a clunky report review UI
  • Self-employed workers waste time hunting for tasks in a chaotic list
  • Self-employed workers ask tech support the same payout questions

Result

  • Shift and task management time down from (6–7 h → 120 min estimated)
  • Moderation task time down by 14%
  • Attracted and retained Tele2 (Sweden) and Japan Tobacco International
  • Fixed self-employed UX (support reported fewer questions)

Fails

  • Designed a cumbersome access control tool that was mostly not adopted
  • Designed a “Task waves” feature that was not adopted at all

Set shifts for a slice

JTBD №1

When an enterprise client wants to inspect retail shelves across the whole country, and I must set tasks in a plain table, I want slightly different tasks to appear automatically for each geo slice (state, city, district). This way, I avoid most of the manual work.

As a solution, I designed a calendar with easily configurable nested nodes. A manager can pick a geo slice, such as a city district, to create a specific schedule and assign workers in bulk.

The first alternative was a visual map, but it requires effort to map zones and is hard to scale and support. The second was an auto algorithm, but it is overkill for irregular activities and beyond team resources.

As a result, I removed Excel imports and exports and the manual work with a plain locations list. Task time dropped from 6–7 hours to an estimated 120 minutes.

Why nested nodes?

JTBD №2

When I post tasks in risky or remote locations where workers won’t go without extra pay, I want location-based reward rules applied automatically, so I stop hand-tuning rewards and spending time chasing coverage

Nested nodes let managers set location-based rules. A rule set on a node is inherited by all locations beneath it. For example, a manager can set an extra reward on a region node. It then applies automatically to every location under it, without manual setup for each one.

Users cannot see the reward amount. The calendar supports task schemes built in a low-code platform. Each scheme may use a different reward model: per picture, per hour, or per completed shift. The amount depends on the scheme, so it cannot be shown as a single number in the calendar.

Difficult trade-offs

JTBD №3

When I’ve scheduled tasks for staff or self-employed workers and I’m waiting on completion, I want to see assignment and completion status broken down by geo region, so I can spot which tasks are still undone and either reassign them to a new worker or message the current one.

The user assigns workers at different geo levels: country, region, city, district, or location. But workers have access at different levels too. One worker may have access to a single location. Another worker may have access to a whole region. Because of this, the list of geo units and the list of workers do not line up and bulk assignment is not clean.

I designed a form that lets the user assign workers at the base level chosen by business needs. The base level is the smallest geo unit in the schedule. For example, the user assigns tasks district by district. For each district, the form shows only workers with access to that district. This includes workers with city access, region access, or access to a location inside the district. The lists line up, so bulk assignment works.

Self-employed workers pick tasks from a list on their own. It is hard to predict whether they will take a task and finish it. The manager cannot know in advance. So when time is almost up, the manager must either assign a new worker or call the worker who already has the task.

In assignment mode, the manager sees tasks with no assigned workers (by geo level and day) and the number of collected reports. This makes report collection progress easy to see by location, district, city, and so on.
